# 实现与支持范围

项目针对一个已知 Wosee 3.53.4 原始 APK 做局部二进制修改，不是通用去广告引擎。输入 SHA-256 固定在 `policy.py`，不同版本、不同渠道包或损坏文件都会在生成密钥和输出前被拒绝。

## 修改过程

`axml.py` 读取 Android 二进制 XML 的字符串池及元素块。移除完整的广告组件子树时，保留原字符串池、资源映射及剩余节点的原有引用，只更新 XML 总长度。保留内容会再通过 XML 树对比核对。

`dexpatch.py` 读取 classes8.dex 的字符串、类型、方法和类数据，按类名、方法名及签名定位精确的 8 个方法。把指令改为返回 0/false 或 null，剩余代码单元填 NOP，保持原长度、ID 表和偏移。拒绝包含异常处理器或不适合修改的目标方法，并重新计算 DEX SHA-1、Adler-32。

7 个方法是广告启用/配置开关，1 个方法是允许为空的广告平台列表 getter。平台列表为空使相应路径跳过 SDK 对象创建，原分发器和失败回调保留。没有把返回非空广告对象的方法改成 null，也没有移除正常启动依赖。

输出重新封装为 ZIP，使用 zipalign 对齐，再用本地签名密钥生成 v2/v3 签名。构建后验证全部 ZIP CRC、包信息、Manifest、8 个方法的完整指令和签名，并与原包逐项比较，要求只有 AndroidManifest.xml 和 classes8.dex 的条目内容不同。

签名块、ZIP 封装布局和文件长度也会变化；“两个文件”仅指 APK 内条目的解压后内容，不表示整个 APK 只变了两处字节。

## 限制

- 234 指移除的 Manifest 组件声明数量，不能当成 SDK 厂商数量、显示广告条数或动态注册组件数量。
- 大量原 SDK 代码、资源及原生库仍在 APK 内，本项目不宣称清除全部遥测、网络访问或隐私数据收集。
- 没有做流量、内存、耗电或启动速度的对照实验，不提供相关改善百分比。
- 重新签名可能影响依赖官方签名的登录或服务。这些场景尚未完成测试。
- 历史运行检查只到首次登录/隐私确认页，不能推出摄像头监控、推送或所有广告位正常。
- 原始 APK 当前未包含在源码仓库内；需要自行提供匹配原包才能重新构建。

## 工具要求

Python 3.10+，JDK 17+，Android SDK Build Tools 35.0.0+（支持 zipalign `-P 16`）。当前公开 APK 的发布前复核使用 JDK 17 和 Build Tools 36.0.0。

Android 官方工具说明：[apksigner](https://developer.android.com/tools/apksigner)、[zipalign](https://developer.android.com/tools/zipalign)。

## 密钥

本仓库不包含发布 APK 的签名私钥。自行构建默认使用自己的 `.local/keys/`，不要提交或分享该目录。维护者后续发布更新应使用原维护者密钥；换钥后不能直接覆盖已安装版本。
